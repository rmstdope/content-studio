## A test file stayed slow in CI after the cost its bead named was removed

**What happened.** The bead said `imageTakes.test.ts` (27.8 s in CI) paid for decoding 1024×640
pictures. With small fake pictures it ran in 2.5 s alone locally but 13.7 s in CI; a `decodePng`
16 times faster left it at 13.3 s. A benchmark inside the full local run showed `fitToSize` taking
about 60 ms against 2 ms alone. Reproduced in one file: after happy-dom's
`GlobalRegistrator.register()` and `unregister()` had run twice, the same loops went from about
1.5 ms to about 130 ms and stayed there. Looking `Math` up once in the module removed it
(3.4 s in CI).

**Why.** The UI tests' registering and removing of globals, followed by slow reads of `Math` from the
global object in hot loops. Why Bun's engine does not recover is not established.

**Cost.** Two CI runs and about 40 minutes spent on a cause that was only part of it.

**Prevent by.** A section in the qa role's test-time measurements (or `docs/architecture.md`, where
the test setup is described): time a slow file inside the full `bun test` as well as alone, with
`bun test --reporter=junit`, before naming its cost. And a bead to fix it where the UI tests
register happy-dom, since other hot loops (`core/imagePatches.ts`, `paeth` in `services/png.ts`)
likely pay it still.

**Seen before.** None found.
